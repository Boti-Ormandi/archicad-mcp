# archicad-mcp v0.2.1

> **v0.2.1 is the first published package in the native MCP v2 line.** It carries the complete v0.2.0 feature set and, relative to the v0.2.0 sources, only corrects Unix cache-root isolation in release-gate tests. Runtime behavior is unchanged.

## What changed

- The server now runs directly on the native MCP SDK v2 over stdio.
- The public MCP surface is exactly four tools: `list_instances`, `get_docs`, `get_properties`, and `execute_script`.
- Packaged, version-aware command snapshots make Archicad and Tapir documentation discoverable before Archicad is running. The packaged Tapir baseline documents release 1.5.8 of the [Tapir add-on](https://github.com/ENZYME-APD/tapir-archicad-automation) (MIT license); a command's recorded version indicates when it was introduced or last changed, and the snapshot embeds reproducible upstream provenance that the server validates at startup. These latest docs describe current Tapir behavior; they do not prove exact support or schema for every older installed add-on.
- `execute_script` uses a disposable same-account `local_user` process for reliability and cancellation. It is not a sandbox: scripts retain the ordinary authority of the user running the server.

## Default update checks and opt-outs

At startup, when a shared 24-hour TTL permits, the running server performs at most one bounded, nonblocking check of the authoritative upstream GitHub repository ([ENZYME-APD/tapir-archicad-automation](https://github.com/ENZYME-APD/tapir-archicad-automation)). A newer validated stable release's schema is cached under the OS user cache directory and activated live. The active schema is the newer valid schema by strict semantic version between the packaged snapshot and the cache, with equal versions always selecting the packaged snapshot; a newer cache survives restarts and offline use until a newer package supersedes it. Checks read no tokens or credentials, never modify the installed package, run only inside the running server (there is no daemon or timer), and refuse moved release tags, hash mismatches, older releases, and any changed upstream `LICENSE` bytes — a changed license fails closed until a reviewed package release updates the pinned license policy. First use trusts the public GitHub repository, its TLS, and the stable release metadata it presents: the same source you already trust for the Tapir add-on binary. The project operates no feed or signing service.

| Setting | Effect |
| --- | --- |
| `ARCHICAD_MCP_OFFLINE=1` | Forbids all update network access while still loading the newest cached schema; manual updates refuse with an offline error. |
| `ARCHICAD_MCP_AUTO_UPDATE=0` | Disables automatic startup checks without disabling or downgrading any cached schema. |

Manual controls: `archicad-mcp schemas update` requests an immediate check (honoring offline mode), `archicad-mcp schemas status` reports local-only diagnostics, and `archicad-mcp schemas reset` deletes the cached schema and check state.

## Requirements

- Python 3.11 or newer
- An MCP client that supports stdio servers
- A supported Archicad major for live automation
- A Tapir add-on release built for that Archicad major for full native and Tapir capability

Archicad and Tapir compatibility is determined by the active snapshot metadata. A reachable Archicad instance without Tapir keeps native capabilities available and omits Tapir-only capabilities.

## Migrating from 0.1.x

Configure clients to launch the published console command:

```text
uvx archicad-mcp
```

Remove configurations that call package-internal server APIs or require live schema generation, repository submodules, or a manual schema refresh before command discovery. `archicad-mcp doctor --json` provides offline package and schema diagnostics, while `archicad-mcp setup` prints a client configuration without editing files.

See the [README](https://github.com/Boti-Ormandi/archicad-mcp/blob/v0.2.1/README.md) for installation and operation, and the [native v2 release guide](https://github.com/Boti-Ormandi/archicad-mcp/blob/v0.2.1/docs/native-v2.md) for migration and compatibility details.
